## 1. 功能概覽

| 功能 | 說明 |
|---|---|
| HTML 檔案讀取 | 選取本機的 `.html`／`.htm` 跑團紀錄 |
| 新舊格式支援 | 嘗試辨識新版 `.message` 訊息區塊，以及舊版逐則 `<p>` 匯出格式 |
| 技能檢定擷取 | 辨識符合 `CC...<=... (1D100<=數值)` 與可辨識結果標籤的紀錄 |
| 人物統計 | 統計每位人物的檢定總數、各級成功／失敗與成功率 |
| 篩選與搜尋 | 依結果分類、人物／技能關鍵字篩選 |
| 排序 | 依檢定次數、成功率、姓名、大成功或大失敗次數排序 |
| 人物拖曳排序 | 拖曳人物列左側六點把手，自訂顯示順序 |
| 個人結果分布 | 顯示選定人物的結果次數與比例 |
| 人物間比例比較 | 比較人物成功率及成功／失敗、大成功／大失敗次數 |
| 技能明細 | 依技能彙整檢定次數、成功／失敗、大成功／大失敗與成功率 |
| SAN 特別處理 | 可把 SAN 技能放在清單底部，或合併不同 SAN 技能值 |
| 骰值直方圖 | 統計可辨識的最終骰值 1–100；點擊柱子可標示該骰值 |
| 檢定紀錄回顧 | 查看符合篩選條件的紀錄，並嘗試跳至原始 HTML 對應訊息 |
| 亮／暗色主題 | 切換亮色與暗色介面 |
| 本機解析 | 檔案由瀏覽器讀取並解析；此 HTML 的程式沒有將檔案上傳至伺服器的功能 |

## 2. 如何開始使用

### 2.1 準備檔案

準備從 Cocofolia 匯出的**原始 HTML 紀錄檔**，副檔名通常為 `.html` 或 `.htm`。程式主要針對 CocoFolia 新版或舊版匯出結構設計。

建議保留原始匯出內容。

### 2.2 載入檔案

1. 開啟 `技能骰統計分析器`。
2. 在「① 選擇原始紀錄 HTML」區塊按下檔案選擇欄位。
3. 從裝置選擇 `.html`／`.htm` 檔案。
4. 等待解析完成。
5. 查看狀態文字：程式會顯示讀取到的訊息數、辨識出的技能檢定數，以及辨識到的人物數。

檔案讀取是透過瀏覽器的 `File.text()` 完成。選檔後程式會在瀏覽器中解析內容；此版本沒有將檔案傳送到遠端伺服器的程式碼。

### 2.3 建議的分析順序

1. 先看頂端總數，確認檔案是否成功解析。
2. 在結果篩選列檢查六種結果的數量。
3. 在「② 每人統計總覽」確認人物是否辨識正確。
4. 點選一位人物，查看「③ 個人結果分布」。
5. 到「⑤ 個人技能成功／失敗明細」檢查技能分類與 SAN 設定。
6. 點「查看紀錄」或到「⑥ 檢定紀錄預覽／回顧」確認實際紀錄。
7. 若數量看起來不合理，優先檢查原始 HTML 的檢定格式是否符合辨識規則。

## 3. 從選取檔案到完成分析

整體流程如下：

1. **選取 HTML**：只接受檔案選擇欄位允許的 HTML 類型。
2. **讀取文字**：瀏覽器將檔案讀成文字。
3. **建立文件**：以 `DOMParser` 把 HTML 解析成文件節點。
4. **選擇訊息節點**：
   - 若找到 `.message` 元素，就把這些元素當成新版訊息。
   - 若找不到任何 `.message`，就改讀 `body` 的直接子元素中標籤為 `<p>` 的段落，作為舊版格式。
5. **逐則檢查**：把每則訊息的文字取出，將連續空白合併，再檢查是否符合技能檢定格式。
6. **辨識結果**：訊息必須包含可辨識的結果類別，例如「大成功」「一般成功」「失敗」等，否則不建立統計事件。
7. **擷取欄位**：成功辨識後，記錄人物、技能名稱、技能判定目標值、結果類別、骰值文字、日期文字、原文文字與原始節點索引。
8. **建立人物清單**：從已辨識事件的角色名稱去重，並依繁體中文姓名排序。
9. **計算與呈現**：各區塊根據已辨識事件重新統計；搜尋、篩選與顯示選項主要改變畫面所使用的資料子集或呈現方式。
10. **需要時回看原文**：點擊某筆事件的「跳到原文」，程式會打開原始 HTML 預覽並嘗試定位對應節點。

若檔案無法讀取或解析發生例外，狀態列會顯示「讀取失敗：請確認選擇的是原始 HTML 檔案。」若解析成功但沒有符合格式的檢定，可能會顯示 0 次技能檢定；這不一定代表檔案是空的，也可能是紀錄格式不符合程式的辨識條件。

## 4. 哪些內容會被計算

### 4.1 必須同時符合的核心條件

一則訊息要成為統計事件，必須通過程式中的多重檢查：

- 文字包含可辨識的 `CC` 或 `CCB` 檢定格式，並帶有 `<=`。
- 文字中有符合程式預期的 `1D100<=數字` 判定片段。
- 訊息末端能辨識出六種結果之一：`大成功`、`極限成功`、`困難成功`、`一般成功`、`失敗`、`大失敗`。
- 擷取技能判定目標值的正規表示式能成功匹配。

因此，**只有看起來像技能檢定、但缺少預期格式或結果文字的訊息，不會被納入統計**。

### 4.2 會納入的檢定

- 一般技能檢定，且訊息格式符合程式規則。
- 具有可辨識結果標籤的成功、失敗、大成功與大失敗。
- 符合 `CC<=50 (1D100<=50)` 這類格式、但沒有明確技能名稱的檢定；技能名稱會標記為「未標示技能」。
- 符合程式支援的公式型門檻，例如 `CC<=(75/3) 教育 (1D100<=25)`；技能判定目標值取 `1D100<=` 後面的數字，也就是範例中的 `25`。
- 符合格式的 SAN 檢定。SAN 的不同技能值可依設定分列或合併顯示，但原始檢定事件仍保留。
- KP 發出的、符合檢定格式的 NPC 檢定，人物歸類會依程式規則處理，通常歸在 `KP` 名下。

### 4.3 成功與失敗各包含什麼

- **成功合計**：一般成功＋困難成功＋極限成功＋大成功。
- **失敗合計**：失敗＋大失敗。
- **大成功**：獨立分類，會納入成功合計。
- **大失敗**：獨立分類，會納入失敗合計。

所以總覽的「失敗（含大失敗）」與技能明細中的「失敗」欄位，都是把一般失敗與大失敗合在一起的失敗總數；另外仍會有獨立的「大失敗」欄位供查看。

## 5. 哪些內容不會被計算

以下內容在目前程式規則下不會形成技能檢定事件，或不會進入特定統計：

| 內容 | 處理方式 |
|---|---|
| 一般對話、敘述、角色扮演文字 | 不計入技能骰統計 |
| 純骰值／單純擲骰訊息 | 若不符合技能檢定格式與結果標籤，不計入 |
| 只有 `CC<=...`，但缺少可辨識的 `(1D100<=數字)` 片段 | 不計入 |
| 有 `CC` 字樣但無法辨識六種結果之一 | 不計入 |
| 結果文字不是程式支援的六種分類 | 不計入 |
| 技能目標值或整體檢定片段無法匹配 | 不計入 |
| 只存在於 HTML 其他區域、而非程式選取的訊息節點中的文字 | 不一定會被掃描；依新版／舊版節點選擇規則決定 |
| 骰值無法解析為 1–100 的整數 | 不進入骰值直方圖；但若該事件本身已成功辨識，仍可能計入檢定與結果統計 |
| 技能名稱沒有出現 | 不會因此必然排除；若其餘格式符合，會列為「未標示技能」 |

### 重要差異：不納入統計，不等於不在原始檔案

原始 HTML 預覽可能仍看得到一般對話、純骰值或未被辨識的訊息。它們只是沒有被建立成統計事件，不會因此從原始檔案刪除。

此外，人物清單是從**已辨識的技能檢定事件**建立的。因此，只有一般對話、完全沒有可辨識技能檢定的人物，不一定會出現在人物統計清單中。

## 6. 結果分類與統計公式

### 6.1 六種原始結果

程式使用以下六類，並以原始紀錄中辨識到的結果標籤為準：

| 結果 | 是否計入成功合計 | 是否計入失敗合計 |
|---|---:|---:|
| 大成功 | 是 | 否 |
| 極限成功 | 是 | 否 |
| 困難成功 | 是 | 否 |
| 一般成功 | 是 | 否 |
| 失敗 | 否 | 是 |
| 大失敗 | 否 | 是 |

程式不會根據骰值、技能值或規則書自行重算結果分類。即使某個結果看起來與技能值不一致，程式仍以紀錄中成功辨識的結果標籤作分類。

### 6.2 核心計算

設某資料集合內：

- \(N\)：已辨識事件總數
- \(S\)：成功類事件數
- \(F\)：失敗類事件數
- \(C\)：某一指定結果類別的事件數

公式：

- **總檢定數**：\(N =\) 該資料集合內的事件筆數
- **成功合計**：\(S =\) 大成功＋極限成功＋困難成功＋一般成功
- **失敗合計**：\(F = N-S =\) 失敗＋大失敗
- **成功率**：\(S/N \times 100\%\)
- **單一結果比例**：\(C/N \times 100\%\)

若分母 \(N=0\)，成功率顯示為 `—`，不會除以零。

成功率以一位小數顯示，例如 `66.7%`。個別結果的比例也以該資料集合的總檢定數為分母。

### 6.3 範例

假設某角色共有 20 次已辨識檢定：

| 結果 | 次數 |
|---|---:|
| 大成功 | 1 |
| 極限成功 | 2 |
| 困難成功 | 4 |
| 一般成功 | 5 |
| 失敗 | 6 |
| 大失敗 | 2 |
| 合計 | 20 |

則：

- 成功合計 = 1 + 2 + 4 + 5 = 12
- 失敗合計 = 6 + 2 = 8
- 成功率 = 12 ÷ 20 × 100% = 60.0%
- 大失敗比例 = 2 ÷ 20 × 100% = 10.0%

這裡的大失敗既會顯示在「大失敗」獨立欄位，也會包含在 8 次失敗之內；**不會把失敗合計 8 再加上大失敗 2，否則會重複計算**。

### 6.4 各區塊採用的資料範圍不完全相同

- 頂端 KPI「技能骰總數／成功／失敗」：使用全部已辨識事件，不受結果篩選、關鍵字搜尋或人物選取影響。
- 結果分類篩選器的各類數量：各自統計全部事件中屬於該類的筆數。
- 「每人統計總覽」：依目前結果分類篩選計算每人的各類數量；姓名／技能搜尋會另外篩選表格列。
- 「個人結果分布」：使用選定人物的全部已辨識事件，不跟隨頂端結果分類篩選或關鍵字搜尋。
- 「結果比例比較」：使用人物／技能關鍵字搜尋結果，但不套用頂端結果分類篩選。
- 「個人技能明細」與「檢定紀錄預覽／回顧」：依選定人物、明細中的結果下拉選單與技能搜尋計算。
- 骰值直方圖：使用選定人物的全部已辨識事件，並只統計可解析成 1–100 整數的最終骰值。

## 7. 六大區塊與每個小功能

### 頂端：主題切換

- **☀️ 切換亮色／🌙 切換暗色**：切換整個介面的配色。
- 主題切換只影響視覺樣式，不會改變解析、篩選、分類或統計結果。
- 此版本的主題狀態只在目前頁面執行期間套用；程式沒有將主題偏好寫入永久儲存的功能。

### ① 選擇原始紀錄 HTML

- **檔案選擇欄位**：選取 `.html`／`.htm` 檔案。
- **狀態文字**：顯示讀取訊息數、已辨識技能檢定數、人物數，或讀取失敗訊息。
- 載入新檔會重新建立事件與人物清單，並重設人物排序狀態、選定人物及頂端結果分類。
- 檔案不會透過此工具程式碼上傳至伺服器；解析發生在瀏覽器端。

### 頂端統計與篩選列

#### 四個統計數字

1. **技能骰總數**：全部已辨識檢定事件數。
2. **角色／人物數**：在已辨識事件中出現的不同人物名稱數。
3. **成功**：全部事件中的成功合計，包含大成功。
4. **失敗**：全部事件中的失敗合計，包含大失敗。

這四個數字是全資料總覽，不會因選定人物、搜尋關鍵字或結果分類篩選而改變。

#### 六類結果篩選

- 全部
- 大成功
- 極限成功
- 困難成功
- 一般成功
- 失敗
- 大失敗

點選其中一類後，主要會改變「每人統計總覽」採用的事件集合。篩選器旁的數字顯示該類在全資料中的事件數。此篩選不會改變頂端 KPI，也不會直接限制個人結果分布、結果比例比較、個人技能明細或紀錄回顧。

#### 搜尋姓名／技能

- 輸入關鍵字，會用小寫化後的文字比對人物名稱或技能名稱。
- 「每人統計總覽」的列顯示以人物名稱比對。
- 「結果比例比較」會以人物名稱＋技能名稱比對。
- **取消搜尋**：清空關鍵字。
- 此搜尋不是全域套用到每個區塊；個人技能明細另有自己的技能搜尋欄。

#### 排序

可選：

- **檢定次數**：依檢定數由多至少。
- **成功率**：依成功率由高至低。
- **姓名**：依繁體中文姓名排序。
- **大成功次數**：依大成功數由多至少。
- **大失敗次數**：依大失敗數由多至少。

排序使用目前結果分類篩選後的資料計算各人的指標。切換排序時會取消手動拖曳排序狀態，重新依選定排序規則排列。

#### 只看成功／失敗比率

勾選後，「每人統計總覽」會把各種結果類別的分欄改為：

- 成功
- 失敗
- 成功率

此選項只改變總覽表格的欄位呈現方式，不會改變統計公式或原始事件。

### ② 每人統計總覽

表格每列代表一位已辨識人物。欄位可能顯示：

- 人物名稱
- 檢定總數
- 六種結果各自的次數，或成功／失敗／成功率
- 大成功／大失敗次數

**點選人物列**：選取該人物，更新個人結果分布、個人技能明細與紀錄回顧等相關區塊。

**左側六點把手**：用於拖曳調整人物顯示順序。請拖曳把手，而不是單純點擊人物名稱。拖曳只改變顯示順序，不會改變任何統計數字。

若搜尋後沒有符合人物名稱的列，表格會顯示「沒有符合資料」。

### ③ 個人結果分布

- 上方人物按鈕可快速切換要查看的角色。
- 統計卡顯示該人物的總檢定、成功率、成功合計、失敗合計。
- 下方長條顯示六種結果各自的次數及占該人物全部已辨識檢定的比例。
- **骰值分布直方圖**也位於此區塊下方。

本區塊按選定人物統計其全部已辨識事件，不受頂端結果分類篩選器與姓名／技能搜尋欄限制。

### ④ 結果比例比較

每位人物顯示：

- 成功率長條
- 成功次數
- 失敗次數
- 大成功次數
- 大失敗次數

本區塊會套用頂端「搜尋姓名／技能」關鍵字，但不套用頂端結果分類篩選器。人物顯示順序會與人物總覽的排序／手動排序同步。

成功率仍然是成功合計除以該人物在此區塊資料集合內的總檢定數，不是大成功率，也不是只計一般成功。

### ⑤ 個人技能成功／失敗明細

#### 目前人物

下拉選單用來選擇要查看的角色。選擇後，技能表與紀錄列表會跟著切換。

#### 結果

- **全部結果**：顯示該人物符合技能搜尋條件的所有結果類別。
- 也可指定大成功、極限成功、困難成功、一般成功、失敗或大失敗。

此下拉選單會同時影響技能明細與下方紀錄回顧。

#### 技能搜尋與取消搜尋

- 依技能名稱搜尋，不區分英文大小寫。
- 「取消搜尋」清空技能關鍵字。
- 點技能列中的「查看紀錄」會把該技能名稱填入技能搜尋欄，並更新紀錄列表。

#### SAN 群組（置底）

勾選時，SAN 技能列會排在其他技能之後；取消勾選則依一般排序規則排列。

這是**顯示排序**，不會把 SAN 排除，也不會改變 SAN 的成功／失敗分類或總檢定數。

#### 合併 SAN（取最低值）

勾選時，名稱為 `SAN`（忽略大小寫，並去除前後空白）的事件會合併成同一個 SAN 技能列，即使不同檢定的技能值不同也會合併。

- 合併後的檢定數、成功、失敗、大成功、大失敗及成功率，仍由合併群組中的全部原始事件計算。
- 顯示的技能值採該合併群組中最低的技能值。
- 此設定只影響技能明細的分組與顯示，不會刪除或合併原始事件本身。
- 若取消勾選，SAN 會依技能名稱與技能值分開分組。

#### 顯示技能數值

- 勾選：技能名稱顯示為 `CC<=數值 技能名稱`。
- 取消：只顯示技能名稱。
- 此選項只影響顯示，不影響分組、計數或成功率。

#### 技能明細欄位

| 欄位 | 意義 |
|---|---|
| 技能／數值 | 技能名稱；可選擇是否附上技能值 |
| 檢定數 | 此技能列中的已辨識事件數 |
| 成功 | 一般成功＋困難成功＋極限成功＋大成功 |
| 失敗 | 失敗＋大失敗 |
| 大成功 | 大成功事件數 |
| 大失敗 | 大失敗事件數 |
| 成功率 | 成功合計 ÷ 此技能列檢定數 |
| 查看 | 將技能搜尋設定為該技能，並查看符合條件的紀錄 |

技能列預設依檢定數由多至少排列；同數量時再依技能名稱與技能值排序，但若啟用 SAN 群組置底，SAN 會優先排在底部。

程式也會依「成功率是否低於技能值」對成功率文字套用提示樣式。這個比較只是介面提示，不是新的統計指標，也不會改變成功率；對公式型技能門檻，顯示的技能值取自 `1D100<=` 後方的實際判定目標值。

### ⑥ 檢定紀錄預覽／回顧

這裡列出目前選定人物、結果下拉選單與技能搜尋條件所符合的事件，依原始紀錄順序排列。

每筆紀錄可能顯示：

- 結果類別標籤
- 技能名稱
- 可辨識的日期／時間文字
- 骰值文字
- 技能值／判定片段
- 最多 300 個字元的擷取原文（更長時會加上省略號）
- **跳到原文**按鈕

點「跳到原文」後，程式會展開原始 HTML 預覽，並嘗試以事件保存的節點索引定位訊息，將對應節點加上醒目底色與外框。

- **收起原文預覽**：隱藏預覽區。
- 若來源 HTML 結構與預期不同，預覽仍可能顯示原文，但不保證能準確跳到對應訊息。
- 此按鈕是定位原始 HTML 內容，不是跳到線上平台，也不會修改原始檔案。

## 8. 人物選取、拖曳與排序邏輯

### 8.1 點選人物

點擊「每人統計總覽」中的人物列，或點擊「個人結果分布」上方的人物按鈕，會選取該人物。個人技能明細的「目前人物」下拉選單也可切換人物。

切換人物時，個人結果分布、技能明細與紀錄回顧會更新。切換人物也會清除目前選中的骰值柱狀區間。

### 8.2 拖曳六點把手

1. 找到人物名稱左側的六點把手。
2. 按住把手並拖曳。
3. 將人物拖到目標人物列上；目標列會出現提示線。
4. 放開後，人物順序更新。

拖曳改的是人物的顯示順序，並不改變事件資料、人物歸屬、成功率或結果數量。第④區人物比較也會同步使用這個順序。

### 8.3 手動排序與一般排序

- 尚未手動拖曳時，人物順序由排序下拉選單決定。
- 完成拖曳後，手動順序優先於一般排序選項。
- 再次切換排序下拉選單時，程式會取消手動排序狀態，改回依選定規則排序。
- 載入新檔案會重設手動排序狀態。

## 9. 個人技能明細與 SAN 邏輯

### 9.1 技能分組

一般技能依「技能名稱＋技能值」分組。也就是說，同名技能若有不同技能值，通常會分成不同列。

程式以已擷取的 `1D100<=數字` 後方數字作為技能值欄位。對公式型門檻，這是實際判定目標數字，不一定是原始文字中公式的表面數值。

### 9.2 SAN 合併的例子

假設同一角色有以下已辨識 SAN 事件：

| SAN 目標值 | 檢定數 | 成功 | 失敗 |
|---:|---:|---:|---:|
| 60 | 2 | 1 | 1 |
| 45 | 3 | 2 | 1 |
| 30 | 1 | 0 | 1 |

啟用「合併 SAN（取最低值）」後，顯示為一列：

| 顯示技能 | 檢定數 | 成功 | 失敗 | 顯示值 |
|---|---:|---:|---:|---:|
| SAN | 6 | 3 | 3 | 30 |

這個例子說明：最低值只用於合併列的技能值顯示；檢定數和結果統計仍包含 6 筆原始事件。

### 9.3 需要注意的範圍

SAN 合併是依技能名稱是否等於 `SAN` 進行，不是把所有名稱包含「SAN」字樣的技能都合併。SAN 群組置底則只影響排序，兩個選項可以分別開關。

## 10. 骰值分布直方圖

### 10.1 統計什麼

直方圖位於「③ 個人結果分布」內，統計**目前選定人物的全部已辨識技能檢定**中，可從擷取的骰值文字解析成 1–100 整數的最終骰值。

- X 軸：1 到 100 的骰值。
- 每根柱：該骰值出現的次數。
- 柱高：以目前人物出現次數最高的骰值作相對高度基準。
- 最高柱會填滿圖表設定的最大高度；其他柱依比例顯示。
- 下方顯示有效骰值筆數，以及最高單一骰值出現次數。

### 10.2 點擊骰值柱

- 點擊任一柱，該柱變成橘色。
- 文字提示顯示已選骰值與出現次數。
- 再點另一柱可切換選取。
- 按「取消選取」會取消橘色標示。
- 柱狀選取不會篩選技能表或紀錄列表，也不會改變任何統計數字。
- 柱子支援鍵盤聚焦；聚焦後按 Enter 或空白鍵也可選取。
- 手機上可直接點擊柱子；圖表有最小寬度，窄螢幕可左右捲動。

### 10.3 哪些骰值不進直方圖

若擷取到的骰值不是 1–100 的整數，便不會增加直方圖任何一格。這只影響直方圖，不會自動把已辨識的檢定事件從總檢定數中刪除。

## 11. 原文預覽與跳轉

程式會保留原始 HTML 文字，以及每個已辨識事件在被掃描節點集合中的索引。

點擊「跳到原文」時：

1. 顯示原始 HTML 預覽區。
2. 將預覽區捲到畫面可見位置。
3. 嘗試在 iframe 文件中重新找出訊息節點。
4. 依事件保存的索引定位節點。
5. 若找到，為節點加上橘黃色外框與淡色背景，並捲動至該節點。

### 可能無法精準定位的情況

- 原始 HTML 的訊息結構與程式預期不同。
- 新版檔案沒有 `.message` 節點，或舊版檔案不是 `body` 的直接 `<p>` 子節點。
- 預覽文件載入時機或節點數量與原本掃描結果不同。

若定位失敗，程式不會因此重新計算或刪除事件；只代表無法依目前的索引策略精準跳轉。可使用預覽內容人工核對。

## 12. 檔案格式與辨識規則

### 12.1 新版與舊版訊息節點

- **新版模式**：只要文件內找到 `.message`，程式就使用所有 `.message` 元素作為候選訊息。
- **舊版模式**：若完全找不到 `.message`，則只掃描 `body` 的直接子元素中標籤為 `<p>` 的節點。
- 不會在舊版模式下自動掃描所有深層 `<p>`；若匯出 HTML 結構不同，可能漏掉訊息。

### 12.2 檢定格式辨識

程式先檢查訊息是否含有類似以下的檢定片段：

```text
CC<=50 (1D100<=50) 教育？（以原始匯出格式為準）
```

實際擷取技能名稱的程式規則以 `CC`／`CCB`、`<=` 與 `(1D100<=數字)` 的組合為基礎，並支援公式型門檻，例如：

```text
CC<=(75/3) 教育 (1D100<=25) ＞ 25 ＞ 25 ＞ 一般成功
```

以上是說明用的格式示意；是否能辨識仍取決於完整訊息中結果標籤的排列方式。程式會尋找訊息末端符合的結果分類，並以結果文字作為分類依據。

### 12.3 技能名稱與技能值

- 若能從門檻與 `1D100<=數字` 之間辨識技能名稱，就使用該名稱。
- 若技能名稱缺漏或擷取結果不合理，會標記為「未標示技能」。
- 技能值取 `1D100<=` 後方的數字。
- 原始訊息文字、骰值文字、日期文字及來源節點索引會保留，供明細與原文回顧使用。

### 12.4 人物名稱判定

程式針對兩種格式使用不同策略：

- **舊版格式**：嘗試讀取訊息節點內的 `span`，以第二個 `span` 的文字作為發言者；`KP` 保留為 `KP`，`GM` 有特殊處理。
- **一般／新版文字**：嘗試從日期前方的文字推定發言者；以 `KP` 開頭的訊息歸為 `KP`。若前綴為 `GM` 或空白，則嘗試從支援的彩色 emoji 方括號標籤中擷取人物名稱。
- 若最後仍沒有可用名稱，可能使用 `未辨識人物`。

人物辨識是依匯出文字與結構推定，並非讀取平台帳號 ID。若原始訊息前綴或 HTML 結構特殊，人物可能被錯分；建議以原文預覽抽查。

## 13. 使用限制與常見問題

### Q1：大失敗有沒有算進去？

**有。** 大失敗是六種正式結果之一，會計入總檢定數，也會計入失敗合計，並另外顯示在大失敗欄位。大成功同理，會計入成功合計並另行顯示。

### Q2：為什麼原始紀錄很多，但技能骰總數比較少？

因為程式只統計符合預期檢定格式、能辨識判定目標值，且有可辨識結果標籤的訊息。一般對話、純骰值、格式不符或缺少結果標籤的紀錄都不會成為統計事件。

### Q3：成功率會重新依骰值判定嗎？

不會。成功率以原始紀錄中已辨識的結果標籤計算；程式不會重新套用遊戲規則來判定成功或失敗。

### Q4：為什麼切換頂端結果篩選後，個人結果分布沒有變？

這是目前程式的設計。頂端結果篩選主要用於每人統計總覽；個人結果分布使用所選人物的全部已辨識事件。技能明細與紀錄回顧則使用第⑤區自己的結果下拉選單。

### Q5：拖曳人物會改變統計嗎？

不會。拖曳只調整人物的顯示順序。若切換排序下拉選單，手動順序會被清除並改回一般排序。

### Q6：合併 SAN 會不會少算檢定？

不會。它只把 SAN 的明細列合併，並以最低技能值作為顯示值。合併列的總檢定數與結果數仍由全部 SAN 事件計算。

### Q7：點擊直方圖柱子後，為什麼紀錄列表沒有變？

柱子選取只用橘色標示所選骰值並顯示出現次數；它不是紀錄篩選器，不會改變其他統計。

### Q8：按「跳到原文」沒有精準跳轉怎麼辦？

確認來源是否為支援的原始 HTML 匯出格式。若結構不同，程式可能無法以節點索引定位，但仍可在預覽中查看原文並人工核對。

### Q9：檔案會傳到網路上嗎？

這份 HTML 的讀檔與解析流程使用瀏覽器端的 `File.text()`、`DOMParser` 和 iframe `srcdoc`。程式本身沒有將所選檔案上傳至伺服器的程式碼。請仍只在可信任的裝置與環境中處理你願意在該裝置上查看的資料。

### Q10：為什麼技能值提示顏色看起來不一樣？

技能明細會把計算出的成功率與該列顯示的技能值比較，若成功率低於技能值，就套用提示樣式。這只是 UI 提示，不會影響事件分類、成功率公式或排序。

## 統計定義速查

- **總檢定數**：成功辨識並建立的技能檢定事件數。
- **成功**：一般成功＋困難成功＋極限成功＋大成功。
- **失敗**：失敗＋大失敗。
- **成功率**：成功合計 ÷ 全部已辨識技能檢定 × 100%。
- **大成功／大失敗**：既是獨立結果分類，也分別包含在成功／失敗合計中。
- **人物數**：已辨識事件中出現的不同人物名稱數。
- **SAN 合併**：只改變個人技能明細的分組與顯示；不刪除原始事件。
- **人物拖曳**：只改變顯示順序；不改變統計。
- **骰值柱選取**：只標示骰值與顯示次數；不篩選其他資料。
- **原文跳轉**：嘗試定位來源 HTML 節點；不修改來源資料，也不改變統計。
